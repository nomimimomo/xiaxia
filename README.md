# 🍤 鲜虾 1.2

独立的 SillyTavern 微信式助手扩展。与「鲜虾鱼板面」分开安装、分开保存数据。

## 安装

1. 解压压缩包，把整个 `shrimp` 文件夹放入酒馆目录的 `public/scripts/extensions/third-party/`。
2. 最终应能看到 `public/scripts/extensions/third-party/shrimp/manifest.json`。不要多套一层文件夹。
3. 刷新酒馆页面。在右下角点击 🍤，或在输入框旁扩展快捷菜单中点击「🍤 鲜虾」。
4. 先停用旧鲜虾脚本，避免两个入口同时出现。不要停用鲜虾鱼板面。

这是扩展文件夹，不是导入酒馆助手的脚本 JSON。不需要安装 Node 依赖或运行构建命令。

需要酒馆提供 `SillyTavern.getContext()`、聊天补全预设管理器、`generateRaw`、文件上传接口和消息事件。对照研究时的 SillyTavern 核心接口开发，尚未连接用户实际酒馆验证版本兼容。


## 1.2 书架与摘抄

底部导航新增「读书」，进入后在「书架 / 摘抄」之间切换。覆盖旧版整个 shrimp 文件夹并刷新即可，旧聊天和订阅不变。

- 书架：原文件入库、三列书架、编辑书名、分组、搜索、排序、多选整理、删除、原文件导出。支持收入 TXT、EPUB、Word、PDF 等原文件，本版不解析正文。封面为书名生成的占位封面。
- 按约定，正文阅读、目录与进度跳转、划线等留到合并鲜虾鱼板面时复用其解析和阅读能力，本版没有新写解析器。界面会明确显示「待接入阅读」。
- 每本书、每条摘抄分别选择「当前浏览器 / 酒馆账户」，支持多选迁移。书籍迁移不自动移动独立摘抄；书中附带的阅读元数据会随书一起保存。
- 迁移先写目标、完整回读核对，再删除原位置；目标失败不删原件。源删除失败时两边可能暂留副本，可重试。目标已有不同版本时停止，避免直接覆盖。
- 摘抄：手动新建和编辑正文、出处、章节、笔记；支持分组、搜索、排序、独立迁移和删除。
- TXT：UTF-8 导入，每个非空行一条摘抄；导出每条一行，不添加编号、出处、笔记。正文中的换行在导出时用空格连接。整理模式有选中条目时导出选中项，否则导出当前筛选结果。
- 浏览器保存采用 IndexedDB，并按酒馆账户名称隔离；清除网站数据会删除本地书架。酒馆保存写入独立账户文件 ame-shrimp-reading-v1.json，不混入聊天提示词，也不会自动发给模型。
- 单本原文件暂限 12MB；酒馆书架文件合计暂限 25MB（包含编码后的书籍与摘抄），超过时会提示，原位置保留。浏览器容量由设备与浏览器决定，写入失败会提示。
- 迁移和整理串行执行；请避免多设备同时修改。同浏览器写入有锁，酒馆写入会检查版本与回读，但后端文件接口不提供原子跨设备条件写入。
- 「我」页面原有备份仅包含聊天和设置，不包含独立书架。书籍可在详情导出原文件，摘抄可导出 TXT；TXT 不携带笔记和出处。

## 1.1 新功能与升级

用本包的 `shrimp` 文件夹覆盖 1.0 的同名文件夹，然后刷新酒馆。数据仍使用原账户文件，旧聊天、联系人、开关和动态保留，不需要重新导入。新模块带版本标识，减少更新后仍加载旧缓存的情况。

### 选项与小剧场

聊天顶部新增模式栏：

- 「设置」可以选择日常聊天、小剧场、选项模式，选择读取到最新楼或指定楼层。
- 小剧场借鉴原型的闺蜜线上聊天：短句独立气泡，聊正文高光、槽点和后续；不强行让未邀请人物出场。
- 「选项模式」持续生效，可以直接说“给我生成选项”，也可以点「生成选项」。之后继续讨论、修改，直到满意。点击「退出选项」才退出。
- 设置候选所用口吻：User（绿色气泡代表的用户角色）、当前角色、群成员或自定义人物。候选的提议者和实际行动者分开。
- 默认八类行动选项来自用户提供的小剧场模板，可修改数量、顺序与附加要求。预设里相关 Prompt 可设为仅在此会话选项模式启用。
- 每条候选一个气泡。点气泡把正文放入酒馆 `#send_textarea` 输入框，不自动发送、不追加到已经生成的正文。已有输入时选择追加、替换或取消。
- 候选绑定故事和所读楼层；切换到别的故事不能误填。正文已改变时会先确认。点候选旁的「编辑」可修改文字。

日常聊天可关闭“读取当前正文及历史”；小剧场和选项模式始终读取指定楼及之前的历史。仍遵守上下文字符预算，并不声称把无限历史全部传给模型。

### 公众号推荐和订阅

默认内置并关注「街巷来信」：港媒报道口吻，简体中文，各故事通用；文章内容仍按各故事分别保存。

聊天时可以要求人格推荐公众号，例如“推荐一个这个世界的街边美食号”。回复会显示公众号名片，含名称、简介、主题与口吻，点「关注」才加入订阅。推荐不自动订阅。同一范围的同名号不会重复添加；可以继续聊需求，让人格调整推荐。

「公众号 → 管理订阅」或「我 → 公众号订阅」可自定义、编辑、关注及取消关注。推荐默认属于推荐时的故事；手动编辑可以改为各故事通用。取消关注保留过去的文章。

每个号有独立的关注主题、文章口吻及简繁设置。美食号按美食角度生成，港媒号按港媒口吻生成。默认简体；模型偶尔输出繁体时，会在本地转换。只转换文字，不把所有公众号改成同一种文风。

新闻生成只使用当前故事可用的已关注公众号；未关注任何号时不发起新闻 API 请求。每篇保存标题、摘要及正文，可按公众号筛选查看。每次文章数是所有已关注公众号的合计上限，受刷新设置控制；没有值得写的新内容可以为空。

## 开始使用

1. 「我 → 预设与 API」选择鲜虾预设，设置跟随酒馆或独立 OpenAI-compatible API。
2. 「通讯录 → 识别预设人格」，查看原文依据，可以修改名字和自我介绍，确认后加入通讯录。
3. 点击联系人名字或头像看名片。名字允许重复，来源预设与内容版本分别保存。原预设更新后重新识别会形成新的版本联系人，旧联系人不自动改动。
4. 点击「聊天」开始私聊，或在通讯录多选联系人创建群聊。群内可同时包含人格和角色卡，右上角可修改群名与成员。
5. Enter 把输入加入待发送批次；Shift+Enter 换行；点击 ↑ 一次提交所有待发消息。没有待发消息时，↑ 重生成上一轮回复。手机可直接输入后点击 ↑。
6. 点击消息气泡编辑或删除。生成期间暂不允许编辑已有消息。重生成只有成功且校验通过才替换旧回复。

## 资料与诊断

聊天输入区「＋」可多选分享角色卡、文风、Prompt 原文，或预览后分享当前正文与世界资料。分享角色卡不会邀请该角色加入群。

文风可通过「我 → 文风资料」导入 TXT / JSON 或手动录入；兼容读取同浏览器旧 `ame-style-management-v05` 中的文风全文。没有假定鲜虾鱼板面新版内部数据结构，不直接修改其资料。

人格可以讨论自身预设、生活和创作。Prompt 诊断要求引用原文；不会自动修改预设，也不把对生成原因的猜测称为内部诊断。

## 朋友圈和公众号

在「发现」进入朋友圈或公众号，通讯录也有公众号入口。两者都读取当前楼层、历史正文和世界资料生成内容。可以只刷新朋友圈、只刷新公众号、同时刷新或关闭自动刷新。没有点赞、评论和用户发动态。

信息流以 User 为浏览者，根据当前故事的正文、人设和所读世界资料生成。发帖者不限于通讯录。不同酒馆聊天独立保存；生成内容不写回正文或世界书。原正文修改后，旧动态保留并标记来源变化。

「我 → 朋友圈与公众号设置」分别控制：

- 酒馆出现新消息后自动刷新。
- 鲜虾聊天成功后同步刷新。
- 每次最多生成数量、历史保留上限、自动生成最短间隔。
- 面板关闭后是否继续后台处理。

所有自动刷新默认关闭。手动刷新不受自动开关和冷却限制，但同一时间只运行一个鲜虾生成任务。完全相同上下文自动跳过；模型判断没有新内容时可返回空列表。自动失败最多补试一次，失败内容可手动重试。降低历史上限会先提示预计清理数量。

自动发现以酒馆事件为主，60 秒检查用于恢复或补偿。浏览器关闭、手机系统挂起页面时不运行。切换故事会隔离待处理任务，生成期间正文发生变化时丢弃过期结果。

## 保存与迁移

数据保存在当前酒馆账户的 `user/files/ame-shrimp-v1.json`，不塞入世界书或主聊天正文。写入后回读版本确认。另一页已写入时停止覆盖，当前内存草稿保留，可以导出后重新读取。

同一账户其他设备安装扩展后可读取已保存的数据。当前打开的页面不会无提示合并远端改动；可使用「我 → 重新读取」。不要两台设备同时编辑，文件接口不提供跨设备原子事务。

「我 → 读取此浏览器的旧版鲜虾」在新数据为空时迁移旧会话。旧版没有明确保存完整群成员及预设版本，导入后需补选成员；可在旧联系人名片的编辑页勾选关联当前所选预设版本。旧浏览器记录不删除。

「导出备份」保留联系人、聊天、信息流、预设快照及设置，不包含自定义 API Key。导入会明确提示替换范围，并下载导入前备份。Key 保存于当前酒馆账户文件中，备份分享前仍应自行核对正文中是否包含个人资料。

## 当前实现边界

- 预设读取针对聊天补全 Prompt 格式；鲜虾只覆盖自己的启用状态，不临时切换或改写酒馆预设。
- 联系人快照只保存 Prompt 及顺序，不复制酒馆连接密钥。版本号为内容摘要，不要求源文件本身带版本字段。
- 执行 Prompt 替换 `{{user}}` / `{{char}}`，并在本次请求的局部空间展开简单 `setvar::名称::文本` 和 `getvar::名称`。用户示例中的 `choice` 指令会提供给选项模式；不写入酒馆变量。任意脚本、嵌套宏和复杂变量链仍未完整支持；分享诊断保持原文。
- 跟随酒馆的生成沿用酒馆当前模型、API、采样和输出上限。自定义 API 的输出上限可独立设置，浏览器直连需要服务支持 CORS。
- 世界资料读取包含全局、聊天、人设绑定、角色绑定及内嵌世界书中的未禁用条目，受字符预算限制；这是资料读取，不是完整复制酒馆的世界书触发扫描器。设定按资料顺序取至上限。User 可知范围由生成提示词约束，不保证模型不会泄露暗线。
- 自动人格识别和所有生成均使用所配置模型，会产生 API 消耗。格式错误保留原数据并提示；不会无限重试。
- 大量聊天目前保存在一个账户文件里，每次消息批次或设置提交写入；不是逐字写回整包。输入草稿停顿 1 秒保存。文件超过 25MB 会提示先备份和整理，头像单个限制 500KB。
- 微信原参考截图未定位，本版根据已确认的双端布局要求制作，待用户实机反馈后再微调。

`tests/browser.mjs` 使用 Playwright 在模拟酒馆页面中验证交互。测试不调用真实模型，不代表已在用户的主题、其他扩展及实际 API 环境验证。

完整源码和测试一并提供。简繁转换内置 opencc-js 1.4.2，离线运行，不从 CDN 加载；许可和数据许可在 vendor 中。
